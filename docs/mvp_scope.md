# 最小可行产品（MVP）功能敲定

> 目标：在 2 周内交付一个可运行、可演示、涵盖主线的原型系统。  
> 原则：优先保证核心链路完整，高级分析和复杂模型作为后续增强。

## 一、MVP 必须实现的功能（P0）

| 功能点 | 具体描述 | 验收标准 |
|--------|----------|----------|
| 数据上传与清洗 | 支持上传 CSV，验证必要字段，自动排序日期，展示预览 | 成功上传后显示前10行，字段检查无误 |
| 销售趋势图 | 按日展示总销售额或总销量的折线图 | 图表正确显示，X轴为日期，Y轴为销售额/销量 |
| 热销产品排行 | 按总销量或总销售额展示 Top 10 产品（可切换） | 条形图或表格显示正确排序 |
| 客户细分销售占比 | 饼图展示 Consumer/Corporate/Home Office 的销售额占比 | 饼图显示正确百分比 |
| 销量预测（按类别） | 用户选择产品类别和预测天数（7/14/30），返回预测曲线 | 图表显示历史30天+未来预测值，数据合理 |
| 简单登录 | 硬编码用户名密码（admin/admin），登录后跳转主页 | 错误密码提示，正确密码进入系统 |
| 页面框架 | 至少包含：登录页、数据管理页、销售分析页、预测页、预警页 | 5个页面可互相跳转，布局整洁 |

## 二、MVP 应尽量实现的功能（P1 — 争取完成）

| 功能点 | 具体描述 | 备注 |
|--------|----------|------|
| 折扣效果分析 | 柱状图展示不同折扣区间的平均销量 | 数据集中已有折扣字段，容易实现 |
| 地区销售分布 | 按 Region 或 Country 展示销售额占比 | 可提升演示专业度 |
| 利润分析 | 展示利润最高的产品类别或产品 | 利用 Profit 字段 |
| 支付方式偏好 | 展示不同支付方式的订单量占比 | - |
| 预测时提供基线模型对比 | 在预测页同时展示移动平均预测结果 | 体现 AI 优势 |
| 图表交互 | 悬停显示数值、图例点击筛选 | 提升用户体验 |
| 图表数据导出为 CSV | 每个图表提供下载按钮 | - |

## 三、MVP 暂不实现的功能（P2 — 后续扩展或文档说明）

- 库存预警（因 database 暂无库存字段）
- 用户画像与个性化推荐
- 竞品分析与营销效果评估
- 实时数据流处理
- 多用户权限管理（仅硬编码登录）
- 深度学习模型（LSTM 等）
- 自动邮件预警
- 导出报表为 PDF/Excel

## 四、MVP 交付清单

1. **可运行的程序包**：
   - 后端代码（FastAPI）
   - 前端代码（HTML/JS 或 Streamlit）
   - 数据库文件（SQLite 初始化脚本）
   - 运行说明（README.md）

2. **示例数据**：
   - 清洗后的 CSV 文件（至少 500 行）
   - 日销量聚合表（用于快速演示）

3. **演示素材**：
   - 关键页面截图（至少 5 张）
   - 5 分钟演示视频（涵盖主线操作：上传→分析→预测→预警）

4. **文档**：
   - 需求分析文档（MVP 范围标注）
   - 设计文档（架构图、ER图、接口文档）
   - 测试报告（至少 5 个核心测试用例）

## 五、MVP 开发优先级建议

1. 第1周：搭建项目骨架（Git、目录、基础 Flask/FastAPI），完成登录页和数据上传页原型。
2. 第2周：实现数据清洗和日销量聚合，开发销售分析页（趋势图、热销排行、客户细分）。
3. 第3周：训练 LightGBM 模型并封装预测接口，前端对接预测页。
4. 第4周：实现库存预警逻辑，完善预警页，联调整体流程。
5. 第5周：测试、修复 Bug、制作演示视频和文档。

## 六、风险控制

- 如果预测模型训练时间过长或效果差，**可先用移动平均作为默认预测**，LightGBM 作为后端可选。
- 前端如果开发困难，**立即切换为 Streamlit**，可快速实现图表和交互。
- 数据负责人必须尽快提供干净的日销量表，否则后续阻塞。
