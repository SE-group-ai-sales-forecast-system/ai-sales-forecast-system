# 算法A答辩PPT页级大纲（6/19）

## 第 1 页：算法A在系统中的位置

标题建议：算法A：稳定可解释的销量预测底座

核心要点：

- 输入：真实电商订单 CSV，按日期和商品品类聚合销量。
- 输出：未来 7、14、30 天预测销量，供预测页和库存预警链路调用。
- 默认模型：7 日移动平均。
- 增强路径：LightGBM 可用时走主模型，不可用或异常时回退算法A基线。
- 接口契约：`/api/predict` 请求和响应字段保持稳定。

讲解句：

算法A的定位不是追求复杂模型，而是保证预测链路在任何演示环境下都能稳定输出，让前端预测页和库存预警页不会因为模型依赖问题中断。

## 第 2 页：为什么选择移动平均

标题建议：为什么默认使用 7 日移动平均

核心要点：

- 可解释：未来销量来自最近 7 天平均需求，评委容易理解。
- 可复现：只依赖历史日期、品类和销量，不依赖额外训练文件。
- 稳定：未知类别、异常天数、LightGBM 缺失时仍能返回兼容结构。
- 适合课程项目：重点展示完整软件工程链路，而不是做算法竞赛。

讲解句：

移动平均不是最复杂的模型，但它是最稳的兜底模型；在课程项目里，接口稳定和演示闭环比盲目堆模型更重要。

## 第 4 页：预测链路与回退机制

标题建议：预测接口如何保证稳定

流程：

1. 前端预测页登录后调用 `/api/predict`。
2. 后端 `PredictService` 根据 `model_type` 尝试调用 LightGBM。
3. 如果 LightGBM 缺依赖、缺模型、预测异常或返回结构错误，自动回退到移动平均。
4. 最终统一返回 `product_id`、`predicted_dates`、`predicted_sales`、`confidence_interval`。

讲解句：

这套回退机制保证了默认 lightgbm、显式 baseline 和显式 lightgbm 三种调用方式都能稳定服务前端。

## 第 5 页：真实性、边界与后续优化

标题建议：预测结果真实有效，但不是生产级自动决策

核心要点：

- 真实有效：基于真实 CSV 历史订单数据计算，不是随机数。
- 已验证：日期从 `2026-01-01` 开始，销量非负，7/14/30 天长度正确。
- 可用于：课程演示、趋势参考、库存预警原型和联调测试。
- 不直接用于：真实采购自动下单或生产排程。
- 后续优化：加入促销、节假日、价格、库存、更多历史数据和模型监控。

讲解句：

当前模型满足期末项目的演示和工程闭环要求；如果进入真实业务，需要更多特征、持续回测和人工审批机制。
