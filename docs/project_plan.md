# 基于 AI 智能的电商商品销售分析与预测系统 —— 项目计划与推进方案

> 课程名称：软件工程课程实践  
> 项目类型：企业商业智能（BI）分析系统 / 电商销售预测系统  
> 小组人数：6 人  
> 整理日期：2026-06-09  

## 一、项目定位与核心原则

本项目旨在开发一套面向电商运营人员的“销售分析与预测辅助决策原型系统”。系统将利用真实的电商交易数据，完成销售分析、销量预测、库存预警和可视化报表等核心功能，展示完整的软件工程开发流程。

**核心原则**：
- 先做可运行闭环，再做功能扩展
- 先保证交付完整，再追求模型复杂
- 数据驱动，注重业务可解释性

**采用数据集**：Global E-Commerce Sales Dataset  
- 2000+ 订单记录，15 个字段  
- 时间范围：2023-01-02 至 2025-12-31  
- 覆盖 20 个国家、5 大区域、4 个产品类别、3 个客户细分  
- 包含销量、销售额、利润、折扣、运费等关键指标  

## 二、项目目标与主线

### 2.1 项目目标

利用电商平台历史销售数据，对商品销量、销售额、品类表现、地区分布、客户细分和折扣效果进行分析，并通过机器学习模型预测未来销售趋势，为电商企业运营决策提供数据支持。

### 2.2 系统主线

```
数据导入 → 数据清洗 → 销售分析 → 销量预测 → 库存预警 → 可视化报表
```

### 2.3 扩展分析（基于数据集优势）

- 客户细分分析（Consumer / Corporate / Home Office）
- 折扣效果分析（不同折扣率对销量的影响）
- 全球区域销售分布（5 大区域 + 国家）

## 三、核心功能模块（MVP）

| 功能模块 | 优先级 | 功能说明 |
|----------|--------|----------|
| 数据导入与清洗 | 必须 | 上传 CSV；处理缺失值、日期格式、排序；生成字段检查报告 |
| 销售数据分析 | 必须 | 按时间、产品类别、地区、客户细分统计销量和销售额，展示趋势与排行 |
| 销售趋势预测 | 必须 | 选择产品类别，预测未来 7 / 14 / 30 天销量 |
| 库存预警 | 必须 | 结合模拟库存与预测销量，判断库存不足并建议补货量 |
| 可视化报表 | 必须 | 销售趋势图、热销排行、地区分布、客户细分占比、折扣影响图、预警表 |
| 用户画像（选做） | 可选 | 基于客户名称的简单购买行为分析 |
| 竞品分析（选做） | 可选 | 文档中描述，代码弱化 |

## 四、技术架构

```
前端展示层：HTML + ECharts / Plotly（或 Streamlit）
后端接口层：FastAPI，提供 RESTful API
算法分析层：Python（pandas, scikit-learn, LightGBM）
数据存储层：SQLite（本地轻量数据库）
```

## 七、数据库设计预测（SQLite）

```sql
-- 订单表（原始数据）
CREATE TABLE orders (
    order_id TEXT PRIMARY KEY,
    order_date DATE,
    customer_name TEXT,
    customer_segment TEXT,
    country TEXT,
    region TEXT,
    product_category TEXT,
    product_name TEXT,
    quantity INTEGER,
    unit_price REAL,
    discount_percent REAL,
    total_sales REAL,
    shipping_cost REAL,
    profit REAL,
    payment_method TEXT
);

-- 日销量聚合表（用于预测）
CREATE TABLE daily_sales (
    date DATE,
    category TEXT,
    quantity INTEGER,
    PRIMARY KEY (date, category)
);

-- 预测结果表
CREATE TABLE forecast_results (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    forecast_date DATE,
    category TEXT,
    horizon INTEGER,
    predicted_quantity REAL,
    model_version TEXT
);

-- 库存预警表
CREATE TABLE inventory_warnings (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    category TEXT,
    current_stock REAL,
    forecast_7d REAL,
    safe_stock REAL,
    suggested_order REAL,
    warning_date DATE
);
```

## 八、风险与应对

| 风险 | 概率 | 影响 | 应对措施 |
|------|------|------|----------|
| 预测模型效果差 | 中 | 中 | 先保证基线模型可用，LightGBM 可调整特征；答辩时强调业务价值而非精度 |
| 前端开发时间不足 | 中 | 高 | 优先使用 Streamlit 快速搭建，后期再优化样式 |
| 成员协作冲突 | 低 | 中 | 使用 GitHub Projects 跟踪任务，每周站会同步进度 |
| 数据理解偏差 | 低 | 低 | 2号负责数据字典，全员参与数据探索 |
